# testing/ — Skill Testing Program

This directory is the reproducible, deterministic skill-testing program for the
`pack-core-skills` catalog. It is the vendored testing program from the upstream
[`rlnorthcutt/core-skills`](https://github.com/rlnorthcutt/core-skills) repo,
adapted for multi-model A/B runs keyed by agent profile.

The program is driven by the **`test-skills` skill** (`../skills/test-skills/SKILL.md`),
which teaches any agent — with zero prior context — how to run a full batch. This
README documents the layout, the protocol in brief, and the reproducibility rules.
The authoritative protocol is `TESTING-PLAN.md`; the scoring rubric and JSON schema
are pinned in `SCHEMA.md`.

> **Note on `TESTING-PLAN.md`:** it is kept verbatim as a historical record of the
> protocol. The **results-location change below supersedes it** — fresh runs now go
> to `<skills-dir>/test/<yymmdd>/`, not `testing/results/`. The A/B method, rubric,
> and scoring rules in `TESTING-PLAN.md` remain authoritative.

## Layout

```
testing/
├── TESTING-PLAN.md                 # the A/B protocol, per-skill specs, rubric (vendored verbatim)
├── REPORT.md                       # the historical portfolio report (vendored verbatim)
├── README.md                       # this file
├── SCHEMA.md                       # JSON result schema + scoring rubric, pinned for cross-agent comparability
├── fixtures/                       # reproducible, checksummed task seeds (byte-identical to upstream)
│   └── SHA256SUMS                  # sha256sum manifest — fixtures are immutable (see below)
├── results/                        # (historical) — now only for the archived run; see results-archive/
├── results-archive/                # historical baseline record, preserved for provenance
│   └── 2026-09-deepseek-v4-flash/  # the prior single-model run (upstream results/ + REPORT.md)
└── scripts/
    └── report.py                   # stdlib-only report generator (run-folder + backward-compat modes)
```

**Fresh runs do NOT go under `testing/results/`.** They go to a per-run folder
**relative to the live skills directory**: `<skills-dir>/test/<yymmdd>/` (e.g.
`~/.claude/skills/test/260930/`), where `<yymmdd>` is the actual run date,
suffixed `-2`, `-3`, … if multiple runs happen the same day. Inside that folder:
per skill per profile `<profile-id>/<skill-id>.{md,json}`, plus `SUMMARY.md` and
`report.html` generated by `scripts/report.py --run <run-folder>`.

## What is vendored vs. generated

- **Vendored verbatim from upstream** (do not edit): `TESTING-PLAN.md`, `REPORT.md`,
  and everything under `fixtures/`. These are the reproducibility anchor.
- **Historical baseline, preserved as archive**: the upstream `results/` directory
  and `REPORT.md` from the previous single-model run (deepseek-v4-flash,
  2026-09) live under `results-archive/2026-09-deepseek-v4-flash/`. They are a
  record of *one* model's run, not the current state.
- **Generated fresh**: everything under a per-run folder `<skills-dir>/test/<yymmdd>/`.
  Fresh runs regenerate it. The pack's `testing/results/` is now only for the
  archived historical run — do **not** write fresh results there.

## The A/B protocol (in brief)

Per skill, run **3 trials** (5 for the creator family: `create-agent`,
`create-skill`, `create-tool`). Each trial is run **twice from the identical
starting state**:

- **Baseline** — the task, skill NOT loaded.
- **Treatment** — the same task, skill loaded via `load_skill(name)`.

Score both runs 0–2 per rubric criterion (see `SCHEMA.md`). A skill **passes** if
the treatment average is **≥ 2× the baseline average AND ≥ 70% of the maximum
score**. In addition, run **2 trigger probes** (one positive, one negative) per
skill, scored pass/fail.

Tasks are drawn **only** from `fixtures/` (seeded, with `GROUND-TRUTH.md` anchors).
Never invent task inputs — that is what makes runs comparable across agents and
models.

## Multi-model workflow

The user supplies several agent profiles, each with a different model. Results are
keyed by **profile id** under a per-run folder `<skills-dir>/test/<yymmdd>/<profile-id>/`:

1. Run **one full batch per profile** (all in-scope skills, one session each).
2. After each profile's batch, run
   `python3 scripts/report.py --run <skills-dir>/test/<yymmdd>` to regenerate the
   run's `SUMMARY.md` and `report.html`.
3. `report.html` includes the cross-profile comparison table (rows = skills,
   columns = profiles). Its "baseline average" is the cross-model baseline — the
   reference point for judging each skill's marginal value.

Do **not** mix profiles' results into one directory; the schema and report tooling
assume one profile per directory.

## Reproducibility rules

1. **Fixtures are immutable.** `fixtures/SHA256SUMS` pins every fixture file.
   Verify with `cd testing/fixtures && sha256sum -c SHA256SUMS` before a batch.
   Any fixture change is a **breaking change** and requires a new fixtures version
   (new directory + regenerated checksums) — never edit a fixture in place.
2. **Never invent task inputs.** Use the seeded fixtures and their `GROUND-TRUTH.md`
   anchors for scoring.
3. **Run one skill at a time.** Before launching a trial, verify the spawned/loaded
   brief matches the intended skill (a past incident overwrote the wrong result
   file when a mismatched brief ran).
4. **Write both `.md` and `.json` results** per the templates in `SCHEMA.md`.
5. **Regenerate reports** with `scripts/report.py` after each batch; commit the
   generated reports so the record travels with the pack.

## Regenerating reports

Fresh runs (primary mode) — generate the run's summary + HTML report from the run
folder:

```
python3 testing/scripts/report.py --run <skills-dir>/test/<yymmdd>
```

This writes `SUMMARY.md` and `report.html` inside the run folder. Pure Python
stdlib, no dependencies. Exits 0 even when the run folder is empty (prints a
clear message).

Backward-compatible mode — if records still exist under `testing/results/`:

```
cd testing
python3 scripts/report.py
```

This regenerates each profile's `results/<profile-id>/REPORT.md` and the top-level
`results/COMPARISON.md`. This mode is retained for the archived historical run;
fresh runs use `--run`.
