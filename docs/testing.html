01 · Method

How the tests work

The testing program lives in the testing/ directory. Every skill is validated with a strict A/B protocol that measures the skill's marginal value, not just whether the agent can do the task.

The A/B protocol

Each skill gets 3 trials (5 for the creator family: create-agent, create-skill, create-tool). Every trial is run twice from the identical starting state:

Run A

Baseline

The task is run with the skill not loaded.

Run B

Treatment

The same task is run with the skill loaded via load_skill(name).

Both runs are scored against the same rubric, so the difference between them is the skill's actual contribution.

Scoring rubric

5Rubric criteria
10Max score

Each skill is scored on 5 criteria, each worth 0 to 2 points, for a maximum of 10 per trial:

0Failed: missing, wrong, or caused harm.
1Partially met: present but flawed, inconsistent, or shallow.
2Fully met: correct, complete, no visible defects.

Reproducible fixtures

Trials run against fixtures committed under testing/fixtures/: seeded diffs, planted bugs, mock contacts, and dirty data. Fixtures are checksummed in SHA256SUMS so any two agents can reproduce the same task seeds and produce comparable records.

Full protocol and rubric detail: TESTING-PLAN.md and SCHEMA.md on GitHub.

04 · Framework

The three tiers

The per-skill numbers are easier to read through the framework from the earlier single-model portfolio run, which the report and the pack philosophy reference. Skills fall into three tiers based on how much marginal value they add, and the tier predicts the size of the gap you should expect.

Expected gap

10–20×

Capability-creation skills

These teach the model to do a job it cannot do at all on its own. Baselines fail outright, so the gaps are the largest.

05 · Findings

Key findings

These are the complete findings from the report. We report the failures plainly: they are what demonstrate that the testing program works.

Finding 1

Skills help most where they're needed most.

The Compact model shows the biggest gains (review-code +75%, research +133%), confirming that skills compensate for gaps in the model's built-in capabilities. The Frontier model shows near-zero improvement on most skills — it already does what the skills teach.

Finding 2

Office/media skills have the largest absolute impact.

make-sheets (+233% on Standard), make-slides (+150% on Frontier), make-docs (+67% on Advanced), and draw-charts (+67% on Advanced) are where skills add the most value. These are structured-output tasks where the skill's format requirements (formulas over baked values, assertion headlines, style-based headings) produce measurably better results.

Finding 3

review-security is the only skill that hurts.

Negative improvement on Compact (-50%) and Frontier (-20%). The thoroughness pressure inflates severities and suppresses correct "no findings" verdicts. The diff-attribution and clean-verdict rules added in the refinement commit address this.

Finding 4

simplify-code is unmeasurable.

On Compact the treatment run hallucinated its entire output (ratio -100%). On the other three models the baseline already simplifies perfectly (ratio 0%). No reliable signal.

Finding 5

[NEEDS] marking is the most transferable discipline.

The write-drafts improvement (26% avg) comes almost entirely from baselines inventing names/dates while treatment marks unknowns. This behavior transfers across every model tested.

Strong models get zero marginal value (ceiling effect)

gemini-3.6-flash and glm-5.3-flash score 7 to 10 out of 10 on their baselines without any skill. The skill adds form (severity grouping, verdicts, structure) but no new findings. The strongest models find the same bugs, write the same drafts, and build the same tools with or without skill instructions. Skills are not a substitute for a strong model.

Weak models show the largest skill benefit

This confirms the core hypothesis. gemini-2.5-flash-lite baselines hallucinate APIs, invent findings, and miss planted bugs. On the smallest and cheapest profile, the gains were largest:

Two skills actively made things worse

In specific contexts, skills hurt rather than helped, and both findings drove fixes.

review-security hurt precision · ratio 0.48 The skill's thoroughness pressure inflated severities and failed to teach diff attribution. On deepseek-v4-flash the treatment was worse than baseline: the baseline correctly said "clean diff" while the treatment attributed a pre-existing IDOR to the diff as Critical. All profiles shared the same failure of attributing pre-existing gaps to the diff under review.
research hurt helpfulness offline · ratio 0.45 The deepseek profile had no web access. Baselines answered from training knowledge with honest caveats; treatments hard-stopped per the skill's rule ("if you cannot find a source, say so and stop"), refusing to answer at all. The skill needed an offline fallback: answer from training knowledge with clear dating and staleness markers.

flash-lite reliability findings

gemini-2.5-flash-lite was the least reliable profile, and the findings are specific:

  • Tool use is unreliable for edit tasks: hallucinated reports (claimed edits never made), destroyed a fixture file (overwrote it with invented placeholder code), and claimed test passes against unmodified code. Every claimed edit requires disk verification.
  • Output instability: empty responses, self-duplicated output, and "tool not found" refusals.
  • Provider instability: rate limits and provider errors increased over the session; 7 skills plus 1 partial could not be completed.
  • Review tasks work, edit tasks are dangerous: the model reads code reliably but fabricates when it edits.
  • flash-lite treats skills as tools: briefs must say "Do not load or call any tool or skill."

gpt-oss-20b was excluded

gpt-oss-20b could not produce independent repeated runs: it returned byte-identical output across 6 passes even after think:false and num_predict adjustments. This is a model limitation, not a configuration issue, so the profile was excluded from the results. The full reasoning is documented in EXCLUDED-README.md.

A related note: gpt-6.1-sol was skipped entirely because of persistent upstream rate limits on a new, high-demand model. Zero skills were tested on it.
